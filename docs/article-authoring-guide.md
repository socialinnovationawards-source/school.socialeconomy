# راهنمای نگارش مقاله

محتوای مقاله‌ها در `public/articles/*.md` نگهداری می‌شود. عنوان اصلی، slug پایدار، تصویر، دسته‌بندی، توضیح کوتاه و زمان مطالعه از `src/articles.json` می‌آیند؛ عنوان اصلی را دوباره در متن Markdown به‌صورت `#` ننویسید. برای مقالهٔ تازه، یک `slug` یکتای فارسی و پایدار اضافه کنید؛ تغییر عنوان نباید خودکار مسیر مقاله را عوض کند.

صفحهٔ HTML مستقل و sitemap هنگام build از همین داده‌ها تولید می‌شوند. نویسنده، تاریخ انتشار و تاریخ ویرایش را فقط پس از تأیید تحریریه به داده‌های مقاله اضافه کنید؛ این مقادیر در دادهٔ ساختاریافته استفاده می‌شوند و نباید حدس زده شوند.

## ساختار پیشنهادی

1. با یک مثال، پرسش یا مسئلهٔ روشن شروع کنید و در چند بند کوتاه توضیح دهید مقاله چه چیزی را پاسخ می‌دهد.
2. بخش‌های اصلی را با `##` و زیر‌بخش‌ها را با `###` مشخص کنید. سطح تیتر را نپرید و تیتر را فقط برای متن‌هایی به‌کار ببرید که واقعاً محتوای بخش را معرفی می‌کنند.
3. برای هر بخش یک ایدهٔ اصلی را پیش ببرید. تعریف، مثال و محدودیت‌ها را در بندهای جدا بیاورید تا متن برای مرور سریع هم قابل‌استفاده باشد.
4. در پایان، جمع‌بندی و در صورت مفیدبودن پرسش‌های متداول را بیاورید. منابع را در بخش جداگانه و به‌صورت فهرست ثبت کنید.

## نشانه‌گذاری

- نکتهٔ مهم را فقط در صورت نیاز با نقل‌قول Markdown برجسته کنید:

  `> **نکتهٔ کلیدی:** متن نکته`

- فهرست‌های موردی را با `-` و مراحل مرتب را با شماره‌گذاری Markdown بنویسید.
- جدول‌ها را با جدول استاندارد GFM بسازید؛ از نشانگرهای قدیمی مانند `<جدول>` استفاده نکنید.
- فرمول را در یک خط مستقل بنویسید تا قالب مقاله بتواند آن را از متن عادی متمایز کند.
- برای پیوندها از نشانه‌گذاری Markdown استفاده کنید و برای منابع، نام سازمان یا نویسنده، عنوان و پیوند را تا حد امکان بیاورید.
- HTML خام ننویسید؛ رندرر مقاله برای امنیت، HTML واردشده را اجرا نمی‌کند.

## دقت و خوانایی

- هر ادعا، آمار و مثال عددی باید با منبع یا توضیح روشن پشتیبانی شود. مثال فرضی را صریحاً فرضی معرفی کنید.
- تعریف‌ها و اصطلاحات تخصصی را در اولین استفاده توضیح دهید و از تکرار یک نکته در چند بخش بپرهیزید.
- جمله‌ها را روشن و سنجیده بنویسید؛ نکته‌های برجسته مکمل متن‌اند و جایگزین توضیح کامل نیستند.
- بخش‌ها و تعداد نکته‌ها را با موضوع و طول مقاله تطبیق دهید؛ الگو راهنماست، نه سهمیهٔ اجباری.

پس از ویرایش مقاله‌ها، `npm run validate:articles` را اجرا کنید و سپس `npm run build` را بررسی کنید.
